# 彩票管理 H5 应用 - 需求规格文档

## 1. 项目概述

### 1.1 产品名称
**彩票智查** - 智能彩票管理与预测助手

### 1.2 产品定位
面向普通彩民的移动端 H5 应用，提供彩票号码识别、开奖查询、中奖判断、历史记录、智能预测和数据统计等一站式服务。

### 1.3 核心价值
- **省时**：拍照自动识别，无需手动输入
- **准确实时**：联网查询最新开奖，自动判断中奖
- **智能**：AI 预测推荐，多模型可选
- **透明**：清晰统计购彩花费与收益

---

## 2. 用户画像

### 2.1 主要用户
- **年龄**：25-55 岁
- **特征**：定期购买彩票，希望管理投注记录，跟踪中奖情况
- **痛点**：
  - 手动输入号码容易出错
  - 忘记核对开奖结果
  - 难以统计长期投入产出
  - 需要参考预测号码

### 2.2 次要用户
- 偶尔购彩的轻度用户
- 合买团组织者

## 3. 功能需求（详细）

### 3.1 用户认证模块

#### 3.1.1 注册
- **触发位置**：登录页的"注册"链接
- **流程**：
  1. 输入邮箱地址
  2. 输入密码（至少6位）
  3. 确认密码
  4. 获取邮箱验证码（可选，或直接发送验证邮件）
  5. 点击链接激活账号
- **约束**：
  - 同一邮箱只能注册一次
  - 未验证邮箱的账号功能受限（仅能查看，不能保存）

#### 3.1.2 登录
- **输入**：邮箱 + 密码
- **功能**：
  - "记住我"选项（延长会话有效期）
  - "忘记密码"链接

#### 3.1.3 找回密码
- 输入注册邮箱
- 发送重置链接到邮箱
- 点击链接进入密码重置页面
- 输入新密码（至少6位）

#### 3.1.4 退出登录
- 清除本地登录状态
- 返回登录页

### 3.2 彩票识别与查询模块（核心）

#### 3.2.1 拍照识别
**触发**：首页"拍照识别"按钮

**流程**：
1. 请求相机权限（后置优先）
2. 用户对准彩票拍照
3. 调用**百度智能云通用文字识别 API**（v3 最新版）
4. 解析识别出的文本，提取以下信息：
   - **期号**（如：2024050、2025025）
   - **投注号码**：
     - 双色球：6个红球（1-33）+ 1个蓝球（1-16）
     - 大乐透：5个前区（1-35）+ 2个后区（1-12）
     - 其他彩票：按格式识别
   - **投注类型**：单式/复式/胆拖（可选识别）
5. 将识别结果填充到确认页面，用户可手动修正

**识别策略**：
- 支持多张彩票连续识别（批量模式）
- 提供"重新选择"按钮
- 识别失败显示错误并提示重试

#### 3.2.2 开奖查询
**触发**：识别成功后自动查询，或手动点击"查询开奖"

**流程**：
1. 根据期号查询官方开奖数据
   - 需要稳定的开奖数据源（如：彩票官网、第三方API）
   - 建议：自建代理服务器缓存历史数据
2. 获取开奖号码
3. 与用户投注号码逐项比对
4. 判定中奖等级（依据各彩票规则）

**中奖判定规则**：
- **双色球**：
  - 一等奖：6红+1蓝
  - 二等奖：6红+0蓝
  - 三等奖：5红+1蓝
  - 四等奖：5红+0蓝 或 4红+1蓝
  - 五等奖：4红+0蓝 或 3红+1蓝
  - 六等奖：2红+1蓝 或 1红+1蓝 或 0红+1蓝
- **大乐透**：
  - 一等奖：5前区+2后区
  - 二等奖：5前区+1后区
  - ...（需完整规则表）

**结果展示**：
- 显示开奖期号、开奖日期、开奖号码
- 高亮匹配的号码
- 显示中奖等级和奖金金额
- 若未中奖，显示 matched 数量

#### 3.2.3 保存记录
用户确认后，保存以下数据到服务器（关联用户ID）：
```json
{
  "userId": "string",
  "lotteryType": "double-color-ball" | "super-lotto" | "...",
  "period": "2024050",
  "betNumbers": {
    "red": [1,5,12,19,23,29],
    "blue": 14
  },
  "drawResult": {
    "date": "2024-05-09",
    "red": [...],
    "blue": 14
  },
  "match": {
    "redCount": 3,
    "blueMatch": false,
    "prizeLevel": "四等奖",
    "prizeAmount": 200
  },
  "createdAt": "2025-06-20T03:30:00Z"
}
```

### 3.3 历史记录模块

#### 3.3.1 记录列表
- 按时间倒序展示所有投注记录
- 分页加载（每页20条）
- 每条记录卡片显示：
  - 期号 + 彩票类型图标
  - 投注号码（小球展示）
  - 开奖结果（如果有）
  - 中奖标签（等级 + 金额）
  - 投注日期

#### 3.3.2 记录详情
点击记录卡片进入详情页：
- 完整信息展示
- 可编辑（修正识别错误）
- 可删除（确认后删除）

#### 3.3.3 筛选与搜索
- 按彩票类型筛选
- 按中奖状态筛选（全部/已中奖/未中奖）
- 按时间范围筛选
- 按奖级筛选

### 3.4 智能预测模块

#### 3.4.1 模型配置
**入口**：设置页"AI预测配置"

用户可为每个支持的彩票类型配置：
- **模型提供商**：下拉选择（如：阿里云通义千问、OpenAI ChatGPT、DeepSeek、Moonshot Kimi、本地 Ollama）
- **API 地址**：输入框（可手动填写 OpenAI 兼容接口）
- **模型 ID**：如 `qwen-max`、`gpt-4o`、`deepseek-chat`
- **API Key**：加密存储
- **测试连接**：按钮验证配置是否正确

**预设模板**：
- 通义千问（阿里云）：自动填充地址和模型名
- OpenAI 官方：api.openai.com
- DeepSeek：api.deepseek.com
- 本地 Ollama：http://localhost:11434

#### 3.4.2 预测生成
**触发**：预测页"生成推荐"按钮

**流程**：
1. 用户选择彩票类型（双色球/大乐透）
2. 选择推荐的组数 X（1-10）
3. 调用大模型 API，发送 Prompt：
   ```
   你是专业的双色球分析师。根据最近100期的开奖数据（提供统计），请分析：
   - 冷热号趋势
   - 奇偶比例
   - 和值范围
   - 连号可能性
   
   请推荐 X 组下期号码，每组包含6个红球（1-33不重复）+1个蓝球（1-16），并简要说明推荐理由。
   ```
4. 解析大模型返回的 JSON 结果：
   ```json
   {
     "recommendations": [
       { "red": [1,5,12,19,23,29], "blue": 14, "reason": "..." },
       ...
     ]
   }
   ```
5. 展示推荐结果（小球动画）

**历史数据来源**：
- 自建开奖数据库（从官方API抓取并缓存）
- 若无足够历史，使用默认数据集

#### 3.4.3 预测记录
- 保存每次预测的请求和结果
- 可查看历史预测（用于对比实际开奖，未来可计算命中率）

### 3.5 统计报表模块

#### 3.5.1 年度概览
**位置**：首页下拉或"统计"标签页

**指标**：
- 本年度购彩总花费（元）
- 本年度中奖总金额（元）
- **ROI**（投资回报率）= (中奖金额 - 花费) / 花费 × 100%
- 投注次数
- 中奖次数
- 最高单次中奖金额

**计算逻辑**：
- 按"投注记录"的创建时间（或开奖时间）过滤本年度数据
- 花费：每张彩票面值（默认2元）求和
- 中奖：prizeAmount 求和

#### 3.5.2 趋势图表（可选）
- 月度花费 vs 中奖柱状图（Canvas/Chart.js）
- 奖级分布饼图
- ROI 趋势折线图

## 4. 非功能需求

### 4.1 性能
- 首屏加载时间 < 2s（4G网络）
- 拍照识别响应 < 5s
- 预测生成 < 30s（取决于大模型速度）

### 4.2 兼容性
- iOS Safari 12+
- Android Chrome 80+
- 适配主流屏幕尺寸（360x640 ~ 414x896）

### 4.3 安全性
- 密码加密存储（后端）
- API Key 加密存储（前端）
- HTTPS 强制（生产环境）
- 防暴力破解：登录失败限制

### 4.4 可用性
- 支持离线浏览已加载数据
- 弱网环境下友好提示
- 加载状态和错误提示清晰

## 5. 外部接口依赖

### 5.1 百度智能云 OCR
- **服务**：通用文字识别（高精度版）
- **认证**：API Key + Secret Key
- **返回**：JSON 包含识别文本和坐标
- **成本**：按调用次数计费（需查询最新定价）

### 5.2 开奖数据 API
**建议方案A（自建）**：
- 定期从官方抓取并缓存到自建服务器
- 提供 RESTful API：`GET /api/draw?period=2024050&type=ssq`

**方案B（第三方）**：
- 购买付费彩票数据 API（需调研）

### 5.3 大模型 API
**用户自配置**：
- 兼容 OpenAI 格式的接口
- 用户需自行提供 API Key（费用自担）
- 应用仅转发请求，不承担费用

## 7. 技术栈建议

### 7.1 前端（H5）
- **框架**：Vue.js 3 + Composition API（或 React）
- **UI 库**：Vant 4（移动端组件库）或自定义
- **状态管理**：Pinia（Vue）或 Context（React）
- **HTTP 客户端**：Axios
- **图表**：ECharts 或 Chart.js（如需）
- **相机**：WebRTC getUserMedia
- **PWA**：支持添加到主屏幕（可选）

### 7.2 后端（必需）
**方案A（推荐快速启动）**：
- **BaaS**: Firebase / Supabase
  - 认证（邮箱密码）
  - Firestore（数据存储）
  - 云函数（代理 OCR 和大模型调用）
- **优点**：快速开发，免运维

**方案B（自建）**：
- **框架**：Node.js + Express / Python FastAPI
- **数据库**：PostgreSQL / MySQL
- **部署**：Vercel / Railway / 云服务器
- **功能**：
  - 用户认证（JWT）
  - 记录 CRUD
  - 代理百度 OCR API
  - 代理大模型 API（保护用户 Key）

### 7.3 DevOps
- 代码托管：GitHub
- CI/CD：GitHub Actions（自动部署到 Vercel/Netlify）
- 域名：配置 HTTPS
- 监控：Sentry（错误追踪）

## 9. 关键决策点（需您确认）

1. **后端方案**：选择 Firebase/Supabase（快）还是自建 Node.js（灵活）？
2. **开奖数据来源**：官方 API 还是第三方购买？
3. **OCR 成本**：百度智能云按量付费，是否设置每月限额？
4. **大模型限制**：是否设置每日调用次数上限（防滥用）？
5. **隐私策略**：是否收集用户数据？如何使用？
6. **付费模式**：是否收费？如果收费，如何定价？

## 10. 风险与挑战

### 10.1 技术风险
- **百度 OCR 识别准确率**：彩票样式多样，需充分测试
- **大模型响应不稳定**：需要超时、重试、降级策略
- **开奖数据源不稳定**：需要多源备份

### 10.2 合规风险
- **彩票敏感**：需要明确免责声明，不诱导购彩
- **用户数据隐私**：遵守 GDPR/个人信息保护法
- **大模型使用**：用户自担 API 费用和责任

### 10.3 成本风险
- 百度 OCR 调用次数预估（假设每日1000次）：约 ¥50-100/月
- 大模型费用由用户自担（不经过我们账单）
- 后端托管费用（Firebase/Supabase 有免费额度）
