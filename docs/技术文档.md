- **前端框架**: 原生 JavaScript (ES6+)

## 🎨 预测算法详解

### 1. 热门+冷门策略 (`hot-cold`)

**原理**：
- 统计历史开奖数据中红球出现频率（加权：近期更重要）
- 选择出现频率最高的前 10 个热门红球
- 选择出现频率最低的前 5 个冷门蓝球（作为反向选择）

**适用场景**：热号延续、冷号回补

---

### 2. 奇偶平衡策略 (`parity`)

**原理**：
- 计算最近 10 期红球奇偶比例的平均值
- 如果近期奇数偏多，目标奇数设为 3（偶数3个）
- 否则目标奇数设为 4（偶数2个）
- 强制分配奇偶比例

**适用场景**：避免极端奇偶分布

---

### 3. 邻号追踪策略 (`neighbors`)

**原理**：
- 取最近 3 期的所有红球号码
- 计算它们的相邻号码（±1，过滤1-33范围）
- 从相邻号码中随机选择
- 不足 6 个时随机补充

**适用场景**：连号/邻号出现的规律

---

### 4. 余数均匀分布策略 (`remainder`)

**原理**：
- 对 1-33 号球按模6余数分为6组
- 每组随机选择 1 个号码
- 构成 6 个不同余数的号码组合

**适用场景**：余数均匀覆盖

---

### 5. 随机组合策略 (`random`)

**原理**：
- 完全随机选择 6 个不重复的红球
- 随机选择 1 个蓝球

**适用场景**：作为对照组

## 🔒 安全性考虑

### 数据安全
- ✅ 所有数据存储在用户本地（LocalStorage）
- ✅ 无云同步，无账号体系
- ✅ 不收集任何个人信息

### 输入验证
- ✅ 期号非空检查
- ✅ 红球数量必须是 6 个，且不重复
- ✅ 蓝球必须是 1 个
- ✅ 号码范围检查（1-33, 1-16）

### XSS 防护
- 使用 `textContent` 代替 `innerHTML` 插入用户输入
- 动态生成的 HTML 使用模板字符串，但数据经过严格过滤
- 不执行用户输入的 JavaScript

## 🚀 部署指南

### 准备发布

1. 确保 `package.json` 版本号正确
2. 运行 `npm run build`（实际无操作，仅检查）
3. 压缩 CSS/JS（可选）：
   ```bash
   npx terser js/*.js -o js/app.min.js
   npx cssnano css/style.css css/style.min.css
   ```
4. 更新 `index.html` 引用压缩文件

### GitHub Pages

```bash
git init
git add .
git commit -m "release: v1.0.0"
git branch -M main
git remote add origin https://github.com/yourname/lottery-h5.git
git push -u origin main

# 在仓库设置中启用 Pages，选择 / (root) 目录
```

访问：`https://yourname.github.io/lottery-h5/`
